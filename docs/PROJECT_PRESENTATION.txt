EXECUTIVE OVERVIEW
------------------
MOID (internal repository name: RAIS-Pro) is an Enterprise Manufacturing Intelligence 
Operating System specifically engineered for General Managers (GMs), Quality Managers (QMs), 
and production engineers at medical-device manufacturing plants (such as Disposafe in Delhi, 
operating under ISO 13485 and EU MDR 2017 standards).

Plant Excel workbooks enter the system once through Staging. The system automatically profiles 
the sheet structure, resolves plant-specific column names into a verified Mapping Ontology 
Document (MOD), learns plant aliases, and extracts production day-records into an immutable, 
content-addressed event ledger. Every screen—dashboard, SPC, defect drilldowns, COPQ, 
audit trail—is a pure deterministic read over that ledger. Dynamic Data Entry grids are 
automatically generated using the plant's authentic vocabulary.


================================================================================
SLIDE 1: THE SHOP-FLOOR PROBLEM IN REGULATED MANUFACTURING
================================================================================

The Reality:
- Medical device plants produce thousands of daily inspection records across multiple 
  lines, shifts, needle gauges (e.g., 18G, 20G, 22G, 24G, 26G), and assembly stages.
- Plants rely on disparate Excel workbooks created by different shift supervisors.

The Pain Points:
1. Formula Corruption & Math Inconsistencies: Operators accidentally overwrite formulas; 
   sum of defects does not match reported total rejections; yield math breaks silently.
2. Terminology & Schema Drift: One shift writes "BLUNT", another writes "BLUNT TIP", 
   another writes "B.T.", making centralized automated aggregation impossible.
3. The "Black Box AI" Risk: Regulators (ISO 13485 / US FDA / EU MDR) reject non-deterministic 
   or hallucinated metrics. AI cannot be trusted to perform numerical calculations.
4. Double Data Entry: Operators record data on paper/Excel, requiring tedious manual re-entry 
   into rigid ERP software.


================================================================================
SLIDE 2: THE 4 HARD ARCHITECTURAL INVARIANTS
================================================================================

Invariant 1: THE MODEL NEVER DOES MATHS
- AI is strictly constrained to classification (mapping raw column names to canonical entities) 
  and natural language synthesis (drafting CAPA recommendations and chat answers).
- Every number, yield rate, defect count, scrap cost, and SPC threshold is computed by 
  deterministic TypeScript functions in src/lib/analytics/. Zero hallucinations.

Invariant 2: THE LEDGER IS APPEND-ONLY AND CONTENT-ADDRESSED
- Records are never updated in-place or deleted.
- Every event is hashed with SHA-256 over its canonical payload. Re-uploading identical 
  data deduplicates cleanly. Corrections generate audit-tracked CorrectionEvents.

Invariant 3: THE MOD IS THE ONLY INGESTION PATH
- All data enters the ledger through extract-from-mod (for workbooks) or generated direct 
  entry (extractedBy: "direct-entry"). No unverified raw data bypasses ontology validation.

Invariant 4: DATA ENTRY IS GENERATED, NEVER HARDCODED
- The UI conforms to the plant, not the other way around. The entry grid is synthesized 
  from the verified ontology and master catalog, preserving the plant's authentic column names.

SLIDE 4: ONTOLOGY RESOLVER LADDER ALGORITHM
================================================================================

When a column header is analyzed, it passes down an algorithmic ladder:

Stage 1: Exact Index Match (Confidence = 1.00)
- Normalized string lookup against canonical ontology dictionary.

Stage 2: Plant Catalog & Learned Aliases (Confidence = 0.95)
- Matches historical column names verified in previous uploads by the plant team.

Stage 3: Deterministic Regex & Domain Heuristics (Confidence = 0.85 - 0.90)
- Pattern matching for standard manufacturing terms (e.g. /qty\s*checked|insp/i).

Stage 4: Semantic String Distance (Confidence = 0.75 - 0.85)
- Jaro-Winkler & Levenshtein distance against known plant defect lists.

Stage 5: Multi-Model AI Semantic Classifier (Confidence = Variable)
- Contextual LLM classification using MiniCPM / Groq with rigid Zod output schemas.


================================================================================
SLIDE 5: DETERMINISTIC MASS BALANCE & RECOMPUTATION
================================================================================

In medical manufacturing:
Checked Units = Accepted Units + Rejected Units (Sum of all defects)

Spreadsheets frequently contain hidden formula errors. MOID enforces mathematical rigor:
1. Never trusts workbook formulas.
2. Recomputes total defects = Sum(D_1, D_2, ..., D_n) directly from raw atomic cells.
3. Computes Mass Balance Delta:
   Delta = Checked_Qty - (Accepted_Qty + Total_Rejections)
4. Displays exact cell provenance (e.g., "Sheet1!G14") so operators can reconcile 
   discrepancies before committing to the immutable ledger.


================================================================================
SLIDE 6: ANALYTICS, SPC & COPQ ENGINES
================================================================================

Pareto Analysis (80/20 Rule):
- Sorts defect categories in descending order of frequency.
- Computes cumulative contribution percentage.
- Identifies the "vital few" defects responsible for 80% of total scrap.

Statistical Process Control (SPC):
- Computes Centerline (p-bar), Upper Control Limit (UCL), and Lower Control Limit (LCL).
- Evaluates Western Electric and Nelson Rules for out-of-control signals:
  * Rule 1: Point beyond 3-sigma limits (special cause variation).
  * Rule 2: 9 consecutive points on the same side of the centerline.
  * Rule 3: 6 consecutive points steadily increasing or decreasing.

Cost of Poor Quality (COPQ):
- Multiplies physical defect volumes by material cost, labor cost per stage, and 
  disposal overhead to compute direct financial leakage.

================================================================================

All AI calls go through src/lib/ai.ts using a fail-safe execution cascade:

Priority 1: MiniCPM (Self-hosted, on-premises OpenAI-compatible endpoint)
Priority 2: Groq (Llama-3.3-70B-versatile cloud fallback)

Rules:
- Addressed via standard @ai-sdk/openai-compatible. No proprietary SDK sprawl.
- All outputs use structured Zod object schemas.
- If no AI backend is configured, all core deterministic ingestion, analytics, 
  data entry, and reporting features continue working seamlessly.
